## 2. ナレッジ管理

### 2.1 ナレッジの種類

| タイプ | 説明 | 用途 |
|--------|------|------|
| `customer_master` | 顧客マスタ | 顧客コードの提案 |
| `item_master` | 品目マスタ | 品目コードの提案 |
| `account_master` | 勘定科目マスタ | 勘定科目コードの提案 |
| `tax_master` | 税区分マスタ | 税区分の提案 |
| `department_master` | 部門マスタ | 部門コードの提案 |
| `rule` | 業務ルール | 判定ロジックの参照 |
| `exception` | 例外ルール | 特殊ケースの処理 |
| `other` | その他 | 補足情報 |

### 2.2 ナレッジ登録手順

1. **管理画面へアクセス**
   - 組織設定 → ナレッジ管理

2. **新規ナレッジの追加**
   - 「新規追加」ボタンをクリック
   - タイプを選択
   - タイトルを入力
   - 内容を入力（Markdown形式推奨）

3. **OCR設定への紐付け（オプション）**
   - 特定のOCR設定でのみ使用する場合は設定IDを指定
   - 空の場合は全OCR設定で使用

4. **保存と同期**
   - 保存すると自動的に「pending」状態になる
   - 自動同期またはを手動同期でFile Search Storeに反映

### 2.3 ナレッジ編集時の注意

- 編集後は再同期が必要
- 大量編集時は手動同期を推奨
- 同期中のドキュメントは編集しない

### 2.4 ナレッジ削除手順

1. ナレッジ一覧から対象を選択
2. 「削除」ボタンをクリック
3. 確認ダイアログで「削除」を選択
4. File Search Storeからも自動削除される

## 3. 同期操作

### 3.1 自動同期

| タイミング | 説明 |
|------------|------|
| ドキュメント更新時 | Firestoreトリガーで自動実行 |
| 毎日午前3時 | 定期バッチで全組織を同期 |

### 3.2 手動同期

**実行方法：**

```bash
# API経由での手動同期
curl -X POST https://your-domain.com/api/knowledge/sync \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"orgId": "<org-id>", "forceResync": false}'
```

**パラメータ：**

| パラメータ | 説明 |
|------------|------|
| `orgId` | 組織ID（必須） |
| `forceResync` | `true`で全ドキュメントを再同期 |

### 3.3 同期ステータス

| ステータス | 説明 | 対応 |
|------------|------|------|
| `pending` | 同期待ち | 自動/手動同期を待つ |
| `syncing` | 同期中 | 完了を待つ |
| `synced` | 同期完了 | 対応不要 |
| `failed` | 同期失敗 | エラー内容を確認 |

## 4. エラー対応

### 4.1 アラート通知

システムは以下の場合にアラートを送信します：

| アラートタイプ | 重要度 | 対応 |
|----------------|--------|------|
| `sync_failed` | High | 手動再同期またはドキュメント確認 |
| `rate_limit` | Medium | 待機後に自動リトライ |
| `api_error` | High | ログを確認、サポートに連絡 |
| `scheduled_job_failed` | Critical | Cloud Functionsログを確認 |

### 4.2 同期失敗時の対応

1. **エラー内容の確認**
   - 同期履歴で失敗したドキュメントを確認
   - `syncError`フィールドでエラー詳細を確認

2. **原因別対応**

   | 原因 | 対応 |
   |------|------|
   | ドキュメントサイズ超過 | 内容を分割 |
   | File API制限 | しばらく待って再試行 |
   | ストア容量不足 | 不要ドキュメント削除 |
   | ネットワークエラー | 自動リトライを待つ |

3. **手動再同期**
   - `forceResync: true`で再同期を実行

### 4.3 エスカレーション手順

1. 3回以上リトライ失敗 → システム管理者に連絡
2. 全組織で同期失敗 → インフラ障害の可能性、緊急対応
3. セキュリティ関連アラート → セキュリティ担当者に即時連絡

## 5. 監査・レビュー

### 5.1 四半期レビュー

**実施時期：** 1月、4月、7月、10月

**チェック項目：**

#### ナレッジ内容の点検
- [ ] 顧客マスタが最新か
- [ ] 品目マスタが最新か
- [ ] 勘定科目マスタが会計基準と一致しているか
- [ ] 税区分マスタが最新の税制に対応しているか
- [ ] 業務ルールが現行フローと一致しているか
- [ ] 例外ルールが現在も有効か

#### LLM提案品質の監査
- [ ] コード提案の正解率を集計
- [ ] 低信頼度（< 0.5）の提案をサンプル確認
- [ ] ユーザー修正が多いパターンを分析

#### ストア整合性チェック
- [ ] File Search Storeとの整合性確認
- [ ] 同期失敗が続いているドキュメントの確認
- [ ] ストア容量の確認
- [ ] 重複ドキュメントの確認

#### アクセス制御
- [ ] 不要なアカウントがないか
- [ ] 権限が適切か

### 5.2 レビュー記録

レビュー結果は以下の情報を記録：

- 実施日
- 実施者
- 各項目のチェック結果
- 発見事項（Findings）
- 対応アクション（Actions）
- サマリー

### 5.3 監査ログの確認

```bash
# 監査ログの取得（API経由）
# 組織オーナーは自組織のログを確認可能
```

主な監査対象イベント：
- ナレッジの作成・更新・削除

## 6. セキュリティ

### 6.1 アクセス制御

| リソース | 読み取り | 書き込み |
|----------|----------|----------|
| 組織情報 | オーナーのみ | オーナーのみ |
| ナレッジ | オーナーのみ | オーナーのみ |
| 同期履歴 | オーナーのみ | Cloud Functionsのみ |
| OCR履歴 | 設定オーナーのみ | 設定オーナーのみ |
| 監査ログ | オーナーのみ | Cloud Functionsのみ |

### 6.2 データ保護

- すべての通信はHTTPS
- Firebase認証によるトークンベース認可
- 組織ごとにデータを分離
- File Search Storeは内部ネットワークからのみアクセス

### 6.3 認証失敗の監視

- 5回以上の連続認証失敗でアラート
- 不審なアクセスパターンを検知

## 7. トラブルシューティング

### 7.1 よくある問題と対処

#### Q: ナレッジが同期されない

**確認事項：**
1. `syncStatus`が`pending`か確認
2. `syncEnabled`が`false`になっていないか
3. `content`が空でないか

**対処：**
- 手動同期を実行
- エラーログを確認

#### Q: コード提案の精度が低い

**確認事項：**
1. ナレッジの内容が十分か
2. マスタデータが最新か
3. OCR設定に適切なナレッジが紐付いているか

**対処：**
- ナレッジを充実させる
- 低信頼度の提案パターンを分析

#### Q: 同期が遅い

**確認事項：**
1. 同期対象ドキュメント数
2. ドキュメントサイズ
3. API制限状況

**対処：**
- 大量同期は深夜バッチに任せる
- 不要なドキュメントを削除

### 7.2 ログの確認方法

**Cloud Functions ログ：**
```bash
firebase functions:log --only syncOrgLearningDocsHttp
```

**Firestore コンソール：**
- `org_learning_sync_history`コレクションで同期履歴を確認
- `system_alerts`コレクションでアラートを確認
