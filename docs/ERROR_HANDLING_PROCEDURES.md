# エラー対応手順書

## 概要

本ドキュメントは、RAGナレッジ管理システムで発生するエラーへの対応手順を定義しています。

---

## 1. エラー分類と重要度

### 1.1 重要度レベル

| レベル | 名称 | 説明 | 対応時間目標 |
|--------|------|------|--------------|
| Critical | 緊急 | サービス全体に影響、データ損失の可能性 | 1時間以内 |
| High | 高 | 主要機能に影響、一部ユーザーに影響 | 4時間以内 |
| Medium | 中 | 機能低下、回避策あり | 24時間以内 |
| Low | 低 | 軽微な問題、影響限定的 | 1週間以内 |

### 1.2 エラーコード一覧

| コード | 説明 | 重要度 |
|--------|------|--------|
| `AUTH_REQUIRED` | 認証が必要 | Low |
| `AUTH_INVALID_TOKEN` | 無効なトークン | Low |
| `AUTH_PERMISSION_DENIED` | 権限不足 | Medium |
| `SYNC_FAILED` | 同期失敗 | High |
| `SYNC_TIMEOUT` | 同期タイムアウト | Medium |
| `SYNC_STORE_LIMIT_EXCEEDED` | ストア制限超過 | High |
| `EXTERNAL_API_ERROR` | 外部APIエラー | High |
| `EXTERNAL_RATE_LIMIT` | レート制限 | Medium |
| `INTERNAL_ERROR` | 内部エラー | Critical |

## 2. 同期エラー対応

### 2.1 SYNC_FAILED（同期失敗）

**症状：**
- ナレッジドキュメントの`syncStatus`が`failed`
- 同期履歴にエラーが記録される

**対応手順：**

1. **エラー内容の確認**
   ```
   Firestore Console → orgLearningDocs → 対象ドキュメント
   → syncError フィールドを確認
   ```

2. **原因別対応**

   | 原因 | 対応 |
   |------|------|
   | ドキュメントサイズ超過 | 内容を分割して再保存 |
   | File API制限 | 10分待って手動再同期 |
   | 不正な文字列 | 内容を修正 |
   | ネットワークエラー | 自動リトライを待つ（最大3回） |

3. **手動再同期**
   ```bash
   curl -X POST https://your-domain/api/knowledge/sync \
     -H "Authorization: Bearer <token>" \
     -H "Content-Type: application/json" \
     -d '{"orgId": "<org-id>", "forceResync": true}'
   ```

4. **リトライ上限到達時**
   - `syncRetryCount >= 3` の場合
   - ドキュメント内容を手動確認
   - 問題を修正後、`syncRetryCount`を0にリセット
   - 再同期を実行

### 2.2 SYNC_TIMEOUT（同期タイムアウト）

**症状：**
- 同期が60秒以上かかり中断
- 大量ドキュメントの同期時に発生しやすい

**対応手順：**

1. ドキュメント数とサイズを確認
2. 大きなドキュメントを分割
3. 一括同期を避け、少量ずつ同期
4. 深夜の定期バッチに任せる

### 2.3 SYNC_STORE_LIMIT_EXCEEDED（ストア制限超過）

**症状：**
- File Search Storeの容量上限に到達
- 新規ドキュメントが追加できない

**対応手順：**

1. **現在の使用状況を確認**
   ```
   Firestore Console → organizations → fileSearchStoreId
   ```

2. **不要ドキュメントの削除**
   - 古い・使用されていないナレッジを特定
   - ナレッジ管理画面から削除

3. **容量の拡張**
   - プランのアップグレードを検討
   - サポートに連絡

## 3. 外部APIエラー対応

### 3.1 EXTERNAL_API_ERROR（Gemini APIエラー）

**症状：**
- コード提案が失敗
- 同期時のFile Search Store操作が失敗

**対応手順：**

1. **エラー詳細を確認**
   ```bash
   firebase functions:log --only suggestCodesHttp
   ```

2. **Gemini APIの状態を確認**
   - Google Cloud Consoleでステータス確認
   - API クォータを確認

3. **リトライ**
   - 一時的なエラーは自動リトライ
   - 持続する場合はサポートに連絡

### 3.2 EXTERNAL_RATE_LIMIT（レート制限）

**症状：**
- 429エラーが返される
- 大量リクエスト時に発生

**対応手順：**

1. **待機**
   - 指定された`retryAfter`秒待機
   - 通常は60秒

2. **リクエスト量の調整**
   - バッチ処理の間隔を広げる
   - 同時リクエスト数を制限

3. **クォータ増加**
   - Google Cloud Consoleでクォータ増加を申請

## 4. 認証・認可エラー対応

### 4.1 AUTH_PERMISSION_DENIED（権限不足）

**症状：**
- 403 Forbiddenエラー
- リソースへのアクセスが拒否される

**対応手順：**

1. **ユーザーの権限を確認**
   - 組織オーナーかどうか確認
   - OCR設定のオーナーかどうか確認

2. **適切なユーザーで再試行**
   - 組織オーナーアカウントでログイン
   - 正しいトークンを使用

3. **不審なアクセスの場合**
   - 監査ログを確認
   - セキュリティ担当者に報告

### 4.2 認証失敗の連続検知

**症状：**
- 同一ユーザーで5回以上の認証失敗
- アラート通知を受信

**対応手順：**

1. **ユーザーに連絡**
   - パスワードリセットを案内
   - アカウント侵害の可能性を確認

2. **アカウントのロック**（必要な場合）
   - Firebase Authでアカウントを無効化

3. **調査**
   - 監査ログでアクセス元IPを確認
   - 不正アクセスの兆候を調査

## 5. 定期バッチエラー対応

### 5.1 scheduledSyncOrgLearningDocs 失敗

**症状：**
- 毎日午前3時の定期同期が失敗
- Criticalアラート通知を受信

**対応手順：**

1. **ログを確認**
   ```bash
   firebase functions:log --only scheduledSyncOrgLearningDocs
   ```

2. **原因を特定**
   - メモリ不足
   - タイムアウト
   - API制限

3. **手動実行**
   - 個別組織ごとに手動同期を実行

4. **設定調整**
   - 必要に応じてタイムアウト延長
   - メモリ割り当て増加

## 6. データ整合性エラー対応

### 6.1 File Search StoreとFirestoreの不整合

**症状：**
- `syncStatus: synced`だがFile Search Storeにドキュメントがない
- 整合性チェックでwarningが出る

**対応手順：**

1. **不整合の特定**
   - `checkKnowledgeIntegrity(orgId)`を実行
   - 結果を確認

2. **再同期**
   - 不整合のドキュメントを特定
   - `syncStatus`を`pending`にリセット
   - 手動同期を実行

3. **根本原因の調査**
   - 同期履歴を確認
   - エラーパターンを分析
